## Open issues and required evidence

These are source-review findings or explicit contract/SDK questions, not failures observed on a board in this run. They must not be lost behind the passing regressions.

- **O1 — Audio lifecycle and wait semantics (high): code fixed in `0af97427`; controlled hardware stop/restart not covered.** The board now owns PCM rings and uses direct audio-server VFS instead of the opaque SDK PCM helper. Writes honor one wait budget, drain acknowledges prior queued PCM consumption, and close retains writers/drainers/volume operations and blocked VFS callbacks before SDK teardown. Microphone overflow/read predicates share the lifecycle gate; generation tokens reject callbacks from retired sessions, and condition predicates replace stale semaphore tokens. SDK calls run outside the gate. The old helper runtime patch and per-write blocking UART diagnostics are removed. Fail-before/pass-after Clang/GCC fixtures cover deadlines, drain targets, writer/decoder close, stale callbacks/tokens, stop errors and threaded microphone access; TSan passes after repair. See [SDK, host and hardware evidence](./pal-audio-lifecycle.md). The existing board audio-system target exposes startup/streaming but no controlled stop/restart operation; no hardware proof is claimed for that scenario. Final-source full lifecycle acceptance is still required.

- **O2 — BLE stop, callback borrowing and concurrent state (high): code repairs and current-source lifecycle checks passed; SDK limitations remain documented.** Failed encoding preserves payloads (`1c851f81`). GATT unregister retains borrowed callbacks and waits externally without holding a callback lock (`2137527f`); self-unregister returns BUSY. Host stop (`95c1eed2`) now closes admission, retires active PAL/SDK callbacks and pending INIT, checks SDK results, and uses full native host exit before releasing state. Failures preserve ownership; late INIT cannot republish a stopped host. Threaded Clang/GCC fail-before/pass-after fixtures and TSan cover those boundaries. Partial SDK task-creation failure is quarantined because the pinned SDK exposes no verified rollback; reset remains required. Connection/MTU readers and event updates use coherent snapshots (`2bb751b3`); stale, malformed and failed-disconnect events do not alter the active link, and ATT trace reads copy protected storage. Clang/GCC and TSan reproduce the prior faults and pass after repair. Connection-parameter requests (`599562f2`) retain immutable host-owned storage through SDK command consumption; delayed-consumer and submission-interleaving fixtures fail before and pass after, including TSan. Advertising (`057b9a2b`) now separates staged configuration from immutable queued storage, serializes state publication, and retires descriptors through both SDK queues. Deferred reconnect waits for retirement; failed stops and fence submissions preserve ownership. Eleven advertising cases pass under strict Clang/GCC, ASan and TSan after ten fail before repair; the command hook also participates in host retention. See [GATT, host-stop and pinned SDK evidence](./pal-ble-lifecycle.md). Source `1ef68a02` passes three consecutive App BLE statuses after UART install, UART 25/25 and BLE 22/22 twice; see [current-source lifecycle evidence](./pal-o2-lifecycle-hardware.md). Public PAL still fails Filesystem 13 while Core and offline Wi-Fi pass.
- **O3 — Wi-Fi and netif snapshots (high): partially fixed; snapshots and missing-completion recovery still open.** Late scan completion (`1ef68a02`) now publishes task-side cleanup instead of synchronously calling the SDK from its state-machine callback. Strict Clang/GCC reproduce the callback self-deadlock before repair; operation admission reaps completed storage after repair. See [scan lifecycle evidence](./pal-wifi-lifecycle.md). No synchronized snapshot or recovery for a scan that never completes has been implemented yet. The pinned public Wi-Fi header exposes `wifi_off` but no scan cancellation/quiescence API; timeout alone is not proof that result storage can be released.  `wifi_operation_busy` protects task mutations, not `wifi_event`, status reads, snapshot writes or AP client count updates. `sta_connect`/`ap_start` poll fields written by SDK events without synchronization. Events pass shared status storage to synchronous subscribers. `netif` reads raw lwIP DNS and borrowed LAN data outside an established TCP/IP-thread snapshot. Define snapshot ownership without holding a lock across SDK calls that may invoke callbacks or synchronous subscriber calls. Also establish recovery when a timed-out scan never emits completion: the current intentional `SCAN_ABANDONED` ownership then permanently rejects subsequent operations. Needs threaded fake SDK and actual STA/AP/scan-stop recovery evidence.
- **O4 — Event subscriber lifetime and bounded post (design): still open.** No public contract/consumer migration or generation-wrap test was completed. Recommendation: explicitly define synchronous post admission timeout and caller-owned callback lifetime, then audit all consumers; if unsubscribe must quiesce, define self-unsubscribe separately and migrate every provider.  Registry retain/release safely defers registry mutex destruction, including deinit from a handler. It does not retain `handler_user`: unsubscribe can return after the final active check but before invocation. Reference ESP/desktop snapshot fanout also needs a clear caller-lifetime rule; changing only this backend to wait can deadlock self-unsubscribe. Define whether unsubscribe must quiesce callbacks and test accordingly. `post(timeout_ms)` bounds its first lock only; subsequent registry locks wait forever and handlers run synchronously. Clarify whether the timeout bounds admission or total fanout, particularly for BLE/Wi-Fi SDK callbacks. Generation-ceiling comparison also needs an explicit policy if subscription generation wraps.
- **O5 — Console/App physical deadlines (SDK contract): still open.** The existing console and App physical-write loops were re-read, but no end-to-end deadline implementation or failing-before fixture was completed.  Board console read claims nonblocking but waits up to 10 ticks for the writer lock and maps every lock failure to empty input. Console write rounds zero timeout to one tick; after obtaining the lock it has no deadline around SDK `dev_write`. App USB write starts its budget after acquiring the mutex, only checks expiry after a zero-byte write, and uses overflow-prone `ms_to_ticks(ms + 9)`. Command write maps zero timeout to its default and its fixed KCP physical timeout is distinct from the caller budget. Current startup/USB sync unwind and retry ownership are correct for the documented serialized, boot-lifetime owner. Define end-to-end nonblocking/finite-write behavior with the UART/CDC/KCP owners before altering it; require short/partial write, lock contention and disconnected-device tests. Host fixture success does not prove native DMA completion/bounds.
- **O6 — Display/touch/button driver teardown and first use (SDK/hardware): still open.** Native close/EMI completion and ADC/IIC fault coverage are not established; no behavior change was made.  Display close discards nonblocking flush and close results; touch close similarly discards close status. Retention/ownership on a failed native close is unspecified here. Display command bytes use stack storage after nonblocking mode is enabled, so verify whether one-byte EMI writes complete before return. Global display/touch state and first-use ADC registration have no concurrency guard; ADC registration errors and IIC START/STOP errors are ignored. Establish the supported single-owner rule or serialize using a driver-safe design; verify flush failure, close/reopen during transfer, button init failure and IIC recovery. The fixed touch configuration-write failure is independently covered.
- **O7 — Remaining socket state/error contracts: terminal mode fixed; concurrency/DNS audit still open.** The provider snapshots `F_GETFL` before connect and restores the original nonblocking bit on immediate, select, getsockopt and SO_ERROR terminal failures. TIMEOUT/WOULD_BLOCK preserve pending nonblocking mode, following `desktop_net_tcp_connect`. The pinned SDK `include_lib/net/lwip_2_2_0/lwip/src/include/lwip/sockets.h` declares `lwip_fcntl` and maps `fcntl` to it. The extended `jieli_net_timeout_errors_test` fails before at `mode_calls==2 && current_mode==initial_mode` and passes after for both initial modes and all four terminal stages, with Clang/Bazel and Linux GCC. The terminal-error mode defect is fixed in `99423844`; POSIX supplied the reference behavior. Success-path restoration failures are now propagated and fault-injected in c53dc04a. Socket mode and pending retry behavior are now covered by terminal-path fault injection. Concurrent per-socket timeout-option changes can affect another reader/writer; require either a single-owner contract or per-operation readiness semantics. Synchronous `gethostbyname` and borrowed lwIP data require the pinned SDK's reentrancy guarantees. The asynchronous resolver reference/capacity path passed its controlled callback/early-close test.
- **O8 — Core SDK failure/allocator policy: allocator fixed; valid SDK destroy/unlock ownership audited.** The maintainer selected caller-allocator support. Mutex, semaphore, condition and queue retain the creating allocator, including queue storage and child PAL synchronization objects; NULL retains the SDK default. Two ownership fakes and allocation/native-create failure injection fail before on all four paths and pass afterward under Clang/GCC; threaded core tests pass TSan. Native builds pass, followed by public PAL hardware 10/10. See [allocator evidence and SDK ownership limits](./pal-blocker-followup.md) and [hardware result](./pal-allocator-hardware.json). The pinned SDK deletes valid quiescent mutex/semaphore handles without a returned failure; recursive give fails only for the wrong owner (or invalid IRQ/critical-section context in its wrapper). No speculative retry/ownership mode was added. Mandatory condition relock and explicit internal failure ownership remain intact; invalid native objects/external interference are outside that evidence. The separate Core concurrency defect is fixed by `d91c2c1f`, with three untraced PAL passes in `cc6aa666`. Allocator code is in `612758bd`; final-source full lifecycle acceptance remains required.
- **O9 — SD mount/runtime ownership and native errors: mount ownership and stat/directory close reporting fixed; rename/open SDK audit still open.** `sd_mounted` now publishes readiness only after both directories are prepared; `sd_mount_owned` retains PAL-created mounts until a successful unmount, including failed-init cleanup. External mounts survive failed initialization and deinit. The board header requires serialized composition-root teardown after all API users and file handles stop; current in-repo references expose deinit but have no runtime teardown caller. `jieli_sd_mount_test` fails before when failed initialization unmounts an external volume, then passes borrowed/owned, failed cleanup and retry cases. `jieli_sd_directory_test` fails before for directory/stat close failure and now propagates IO without publishing stat output. Native close consumption is unchanged; no failed close is retried. The premature readiness and external-unmount defects are fixed in `8df9468c`. Runtime deinit clears static API storage/unmounts without tracking users or handles. Require serialized composition-root teardown with every user stopped, or introduce explicit ownership/refcounting. `directory_status` and `fs_stat` close errors are fixed in `8df9468c`; `fs_rename` still ignores read-handle close errors; native NULL-open is mapped to NOT_FOUND without distinguishing I/O failure. Before changing return/retain semantics, verify the SDK's close-consumes-handle and open-error reporting behavior. Single-level mkdir and UTF-8 fixes were rechecked and preserved; no new claim about flash/SD power-loss behavior. A later PAL run after audio testing completes Core and Wi-Fi but fails Filesystem 13 at mkdir: the creation handle reports non-directory while reopening the requested entry verifies a directory (`native=-7 lookup=0`). This SDK handle/publication discrepancy remains open; see [recorded failed run](./pal-audio-lifecycle.md).
- **O10 — Coredump cross-core and watchdog origin: still open.** `early_app_boot.patch` invokes reset recovery from `setup_arch`, before the new boot marks Loader ownership; assigning the new boot's `running_loader` there would misclassify the previous boot. A retained previous-role protocol, cross-core capture implementation and watchdog hardware tests remain unimplemented.  Retained log head/total/data and pending record have no cross-core serialization. Do not add a normal spinlock in the assert hook: a halted core may own it. Establish whether the patched producer is already serialized and how snapshots avoid a half-written ring. The watchdog reset hook sets pending but does not set crash origin; Loader-vs-App watchdog recovery classification needs explicit retained origin evidence (the assert path does set it).
