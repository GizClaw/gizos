## Open issues and required evidence

The entries below include subsequent fixes and hardware follow-ups. Remaining contract and SDK questions are explicit; passing regressions do not close those questions.

- **O1 — Audio lifecycle and wait semantics (high): code fixed in `0af97427`; controlled hardware stop/restart not covered.** The board now owns PCM rings and uses direct audio-server VFS instead of the opaque SDK PCM helper. Writes honor one wait budget, drain acknowledges prior queued PCM consumption, and close retains writers/drainers/volume operations and blocked VFS callbacks before SDK teardown. Microphone overflow/read predicates share the lifecycle gate; generation tokens reject callbacks from retired sessions, and condition predicates replace stale semaphore tokens. SDK calls run outside the gate. The old helper runtime patch and per-write blocking UART diagnostics are removed. Fail-before/pass-after Clang/GCC fixtures cover deadlines, drain targets, writer/decoder close, stale callbacks/tokens, stop errors and threaded microphone access; TSan passes after repair. See [SDK, host and hardware evidence](./pal-audio-lifecycle.md). The existing board audio-system target exposes startup/streaming but no controlled stop/restart operation; no hardware proof is claimed for that scenario. Final-source acceptance is recorded in the [2026-09-15 final round](./pal-final-acceptance.md).

- **O2 — BLE stop, callback borrowing and concurrent state (high): code repairs and current-source lifecycle checks passed; SDK limitations remain documented.** Failed encoding preserves payloads (`1c851f81`). GATT unregister retains borrowed callbacks and waits externally without holding a callback lock (`2137527f`); self-unregister returns BUSY. Host stop (`95c1eed2`) now closes admission, retires active PAL/SDK callbacks and pending INIT, checks SDK results, and uses full native host exit before releasing state. Failures preserve ownership; late INIT cannot republish a stopped host. Threaded Clang/GCC fail-before/pass-after fixtures and TSan cover those boundaries. Partial SDK task-creation failure is quarantined because the pinned SDK exposes no verified rollback; reset remains required. Connection/MTU readers and event updates use coherent snapshots (`2bb751b3`); stale, malformed and failed-disconnect events do not alter the active link, and ATT trace reads copy protected storage. Clang/GCC and TSan reproduce the prior faults and pass after repair. Connection-parameter requests (`599562f2`) retain immutable host-owned storage through SDK command consumption; delayed-consumer and submission-interleaving fixtures fail before and pass after, including TSan. Advertising (`057b9a2b`) now separates staged configuration from immutable queued storage, serializes state publication, and retires descriptors through both SDK queues. Deferred reconnect waits for retirement; failed stops and fence submissions preserve ownership. Eleven advertising cases pass under strict Clang/GCC, ASan and TSan after ten fail before repair; the command hook also participates in host retention. See [GATT, host-stop and pinned SDK evidence](./pal-ble-lifecycle.md). Source `1ef68a02` passes three consecutive App BLE statuses after UART install, UART 25/25 and BLE 22/22 twice; see [current-source lifecycle evidence](./pal-o2-lifecycle-hardware.md).
