# Embedded TTF subset

`ttf_subset_c` retains selected Unicode code points from a consumer-owned TTF and emits the resulting font bytes as portable C source and header outputs. The output is size-independent: consumers can create multiple LVGL TinyTTF instances from the same data with `lv_tiny_ttf_create_data_ex`, and LVGL owns the bounded glyph cache for each runtime size. The generated byte array is `const`, so embedded toolchains can place the single TTF payload in read-only data instead of duplicating a bitmap font for every size.

```starlark
load("@gizos//tools/lvgl/ttf_subset:ttf_subset.bzl", "ttf_subset_c")

ttf_subset_c(
    name = "menu_font",
    font = "//assets:font.ttf",
    out_c = "menu_font.c",
    out_h = "menu_font.h",
    ranges = ["0x20-0x7E"],
    symbol = "menu_font",
    symbol_sources = ["menu_symbols.txt"],
)
```

The rule does not own the source font, choose runtime sizes, create LVGL font instances, or provide a fallback font. Those remain consumer responsibilities.

The generated target can be listed in `cc_library.srcs` or `firmware_native_component.native_srcs`; the converter and pinned Python dependency always execute in the host configuration.
