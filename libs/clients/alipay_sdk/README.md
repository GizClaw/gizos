# Alipay vendor SDK adapter

The shared public contract is [h2_alipay.h](../alipay/include/h2_alipay.h). The [PAL SDK bridge](include/h2_alipay_sdk.h) calls the delivered SDK without changing its headers or implementing business RPCs. It owns SDK invocation, return mapping, identity formatting, storage callbacks, diagnostics, time, mutex, entropy, DNS and network-status adaptation through injected PAL APIs. The [ESP adapter](../../../native_component_src/esp-idf6.x/h2_alipay/include/h2_esp_alipay.h) supplies only the default Bluetooth MAC identity and the native raw socket/select/option boundary required by this delivery. The portable sources remain owned here and are compiled by ESP-IDF through `sdk_sources`; the default `:alipay_sdk` target exposes PAL-only configuration and storage adaptation. Only the network binding module is exposed. The ECDH archive is part of the supplied bind_net dependency list; linking it does not establish that a product has approved this security scheme.

Set `ALIPAY_SDK_PATH` to the original delivery's `output` directory and pass `--repo_env=ALIPAY_SDK_PATH` to Bazel. [The manifest](../../../third_party/alipay/sdk_manifest.json) verifies every selected archive and header before exposing caller-owned inputs. The SDK and its redistribution rights remain with the caller; no binary or sample implementation is vendored. Without those inputs, the SDK firmware cannot build. The explicit `//libs/clients/alipay_sdk:bind_net_sdk_archives` preflight materializes and verifies the archive inputs; building the `bind_net_sdk` CcInfo import alone does not compile or link the SDK.

Configure the SDK singleton once before any SDK call and keep borrowed providers alive until hardware reset. Its first initialization result, including failure, is cached across App restarts. The SDK has no callback removal operation. Binding requests call the original SDK directly after successful initialization; there is no local credential, activation, approval or readiness gate. Supply the SDK feature mask appropriate to the actual product. The target selects a stable SDK IMEI identity through its callback; an explicit SN substitution policy may return the factory SN. Preserve that value across registration, binding and later signed requests, independent of modem availability or the current network transport.

The original `vendor_psa.h` callbacks use the injected persistent Pref PAL through [h2_alipay_storage.h](include/h2_alipay_storage.h). Indexed values default to the dedicated `alipay_psa` namespace; successful mutations are committed before returning and storage errors remain negative SDK callback results. A short read reports the required size without modifying the destination. SDK reset clears only this namespace. `vendor_cert.h` certificate writes default to the separate `alipay_cert` namespace and survive PSA reset. Targets may select stable, distinct PSA and certificate namespaces for an explicit device identity policy. Changing from modem IMEI to factory SN must use a separate context so SDK device names and security state are not reused across identities; leave the previous namespaces intact and let the original SDK obtain its own context. An explicit storage override remains available; its legacy `check_ready` member is not invoked. The adapter does not substitute successful storage operations or manufacture credentials.

The bounded [trace](../alipay/include/h2_alipay_trace.h) records only observed SDK/HAL/socket events. The SDK bridge retains the first 16 vendor-log, successful-clock and successful-allocation diagnostics per class, with explicit seen/summarized counters; other operations and nonzero results are retained normally. Numeric HTTP status, Result-Status and RPC errors observed in recognized vendor log formats are retained separately without copying surrounding messages, headers, signatures or tokens. This prevents verbose SDK diagnostics from displacing the final SDK return or observed error codes. Completeness applies to this declared capture policy, not every formatted vendor message. Drain/reset it after the SDK worker joins; it performs no file or console IO during calls. Raw prefixes require explicit private capture and retain the original observed length, digest, prefix length and truncation/drop counters. SDK logs are formatted vendor messages, not a supported HTTP plaintext export. Socket data is below vendor TLS and must not be labeled decoded RPC. No TLS verification or protocol is changed. Complete HTTP headers/bodies, TLS handshake results and signatures require a supported plaintext boundary in a future SDK delivery; they cannot be inferred from a socket trace or PCAP. Operation-Type is recorded only when that exact header is observed in an SDK log.

The target injects Memory, Time, Sync, Crypto, Net, Netif and Pref PALs and product identity callbacks. The ESP facade retains the existing public names and defaults the MAC callback to `ESP_MAC_BT`; it does not select the other providers. `sdk_test` uses the original headers and controlled SDK entry stubs to test PAL error mapping, initialization caching, identity and callback contracts. It does not qualify the vendor binary or online service. Run it explicitly with the original delivery selected: `bazel test --config=macos_arm64 --repo_env=ALIPAY_SDK_PATH //libs/clients/alipay_sdk:sdk_test`. Real qualification builds and flashes the original SDK integration target.
