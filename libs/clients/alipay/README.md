# Alipay bind_net integration

The public contract is [h2_alipay.h](include/h2_alipay.h). The [ESP adapter](../../../native_component_src/esp-idf6.x/h2_alipay/include/h2_esp_alipay.h) calls the delivered SDK without changing its headers or implementing business RPCs. Only the network binding module is exposed. The ECDH archive is part of the supplied bind_net dependency list; linking it does not establish that a product has approved this security scheme.

Set `ALIPAY_SDK_PATH` to the original delivery's `output` directory and pass `--repo_env=ALIPAY_SDK_PATH` to Bazel. [The manifest](../../../third_party/alipay/sdk_manifest.json) verifies every selected archive and header before exposing caller-owned inputs. The SDK and its redistribution rights remain with the caller; no binary or sample implementation is vendored. Without those inputs, host code remains available and native firmware fails. The explicit `//libs/clients/alipay:bind_net_sdk_archives` preflight materializes and verifies the archive inputs; building the `bind_net_sdk` CcInfo import alone does not compile or link the SDK.

Configure the native singleton once before any SDK call and keep borrowed providers alive until hardware reset. Its first initialization result, including failure, is cached across App restarts. The SDK has no callback removal operation. Native configuration alone does not prove credentials or activation: the secure provider must independently validate persistent commissioning evidence, approved features, product enrollment and storage. There is deliberately no default secure storage, RAM credential flag, automatic provisioning, activation, reset or unbind path. A modem-equipped product must provide its actual IMEI, independent of the current network transport.

The bounded [trace](include/h2_alipay_trace.h) records only observed SDK/HAL/socket events. Drain/reset it after the SDK worker joins; it performs no file or console IO during calls. Raw prefixes require explicit private capture and retain the original observed length, digest, prefix length and truncation/drop counters. SDK logs are formatted vendor messages, not a supported HTTP plaintext export. Socket data is below vendor TLS and must not be labeled decoded RPC. No TLS verification or protocol is changed. HTTP headers/bodies, Operation-Type, TLS handshake results and signatures require a supported plaintext boundary in a future SDK delivery; they cannot be inferred from a socket trace or PCAP.
