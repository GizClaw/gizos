# Alipay bind_net integration

The public contract is [h2_alipay.h](include/h2_alipay.h). The [PAL SDK bridge](include/h2_alipay_sdk.h) calls the delivered SDK without changing its headers or implementing business RPCs. It owns SDK invocation, return mapping, identity formatting, storage callbacks, diagnostics, time, mutex, entropy, DNS and network-status adaptation through injected PAL APIs. The [ESP adapter](../../../native_component_src/esp-idf6.x/h2_alipay/include/h2_esp_alipay.h) supplies only the default Bluetooth MAC identity and the native raw socket/select/option boundary required by this delivery. The portable sources remain owned here and are compiled by ESP-IDF through `sdk_sources`; the ordinary `alipay` library does not import SDK headers or archives. Only the network binding module is exposed. The ECDH archive is part of the supplied bind_net dependency list; linking it does not establish that a product has approved this security scheme.

Set `ALIPAY_SDK_PATH` to the original delivery's `output` directory and pass `--repo_env=ALIPAY_SDK_PATH` to Bazel. [The manifest](../../../third_party/alipay/sdk_manifest.json) verifies every selected archive and header before exposing caller-owned inputs. The SDK and its redistribution rights remain with the caller; no binary or sample implementation is vendored. Without those inputs, host code remains available and native firmware fails. The explicit `//libs/clients/alipay:bind_net_sdk_archives` preflight materializes and verifies the archive inputs; building the `bind_net_sdk` CcInfo import alone does not compile or link the SDK.

Configure the SDK singleton once before any SDK call and keep borrowed providers alive until hardware reset. Its first initialization result, including failure, is cached across App restarts. The SDK has no callback removal operation. Binding requests call the original SDK directly after successful initialization; there is no local credential, activation, approval or readiness gate. Supply the SDK feature mask appropriate to the actual product. A modem-equipped product provides its actual IMEI, independent of the current network transport.

The original `vendor_psa.h` callbacks use the injected persistent Pref PAL through [h2_alipay_storage.h](include/h2_alipay_storage.h). Indexed values use the dedicated `alipay_psa` namespace; successful mutations are committed before returning and storage errors remain negative SDK callback results. A short read reports the required size without modifying the destination. SDK reset clears only this namespace. `vendor_cert.h` certificate writes use the separate `alipay_cert` namespace and survive PSA reset. An explicit storage override remains available; its legacy `check_ready` member is not invoked. The adapter does not substitute successful storage operations or manufacture credentials.

The bounded [trace](include/h2_alipay_trace.h) records only observed SDK/HAL/socket events. The SDK bridge retains the first 16 vendor-log, successful-clock and successful-allocation diagnostics per class, with explicit seen/summarized counters; other operations and nonzero results are retained normally. This prevents verbose SDK diagnostics from displacing the final SDK return. Completeness applies to this declared capture policy, not every formatted vendor message. Drain/reset it after the SDK worker joins; it performs no file or console IO during calls. Raw prefixes require explicit private capture and retain the original observed length, digest, prefix length and truncation/drop counters. SDK logs are formatted vendor messages, not a supported HTTP plaintext export. Socket data is below vendor TLS and must not be labeled decoded RPC. No TLS verification or protocol is changed. HTTP headers/bodies, Operation-Type, TLS handshake results and signatures require a supported plaintext boundary in a future SDK delivery; they cannot be inferred from a socket trace or PCAP.

The target injects Memory, Time, Sync, Crypto, Net, Netif and Pref PALs and product identity callbacks. The ESP facade retains the existing public names and defaults the MAC callback to `ESP_MAC_BT`; it does not select the other providers. `sdk_test` uses the original headers and controlled SDK entry stubs to test PAL error mapping, initialization caching, identity and callback contracts. It does not qualify the vendor binary or online service. Run it explicitly with the original delivery selected: `bazel test --config=macos_arm64 --repo_env=ALIPAY_SDK_PATH //libs/clients/alipay:sdk_test`. Real qualification builds and flashes the original SDK integration target.
