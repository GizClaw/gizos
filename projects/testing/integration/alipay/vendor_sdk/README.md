# Alipay vendor SDK adapter

The integration App's internal contract is [h2_alipay.h](../diagnostics/include/h2_alipay.h). The [PAL SDK bridge](include/h2_alipay_sdk.h) calls the delivered SDK without changing its headers or implementing business RPCs. It owns SDK invocation, return mapping, identity formatting, storage callbacks, diagnostics, time, mutex, entropy, DNS and network-status adaptation through injected PAL APIs. The project-owned [ESP adapter](esp_idf/include/h2_esp_alipay.h) supplies the Bluetooth MAC identity and native raw socket/select/option boundary required by this delivery. Portable sources are compiled by ESP-IDF through `sdk_sources`; `:alipay_sdk` exposes PAL-only configuration and storage adaptation. Only the network binding module is exposed. Linking ECDH does not establish product approval of this security scheme.

Set `ALIPAY_SDK_PATH` to the original delivery's `output` directory and pass `--repo_env=ALIPAY_SDK_PATH` to Bazel. [The manifest](../../../../../third_party/alipay/sdk_manifest.json) verifies every selected archive and header. The delivery remains caller-owned; no binary or sample implementation is vendored. The explicit `//projects/testing/integration/alipay/vendor_sdk:bind_net_sdk_archives` preflight materializes and verifies the archive inputs; the `bind_net_sdk` CcInfo import alone does not compile or link the SDK.

Configure the SDK singleton once before any SDK call and keep borrowed providers alive until hardware reset. Its first initialization result, including failure, is cached across App restarts. The SDK has no callback removal operation. Binding requests call the original SDK directly after successful initialization; there is no local credential, activation, approval or readiness gate. Supply the SDK feature mask appropriate to the actual product. The target selects a stable SDK IMEI identity through its callback; an explicit SN substitution policy may return the factory SN. Preserve that value across registration, binding and later signed requests, independent of modem availability or the current network transport.

The original `vendor_psa.h` callbacks use the injected persistent Pref PAL through [h2_alipay_storage.h](include/h2_alipay_storage.h). Indexed values default to the dedicated `alipay_psa` namespace; successful mutations are committed before returning and storage errors remain negative SDK callback results. A short read reports the required size without modifying the destination. SDK reset clears only this namespace. `vendor_cert.h` certificate writes default to the separate `alipay_cert` namespace and survive PSA reset. Targets may select stable, distinct PSA and certificate namespaces for an explicit device identity policy. Changing from modem IMEI to factory SN must use a separate context so SDK device names and security state are not reused across identities; leave the previous namespaces intact and let the original SDK obtain its own context. An explicit storage override remains available; its legacy `check_ready` member is not invoked. The adapter does not substitute successful storage operations or manufacture credentials.

The bounded [trace](../diagnostics/include/h2_alipay_trace.h) records only observed SDK/HAL/socket events. The SDK bridge retains the first 16 vendor-log, successful-clock and successful-allocation diagnostics per class, with explicit seen/summarized counters; other operations and nonzero results are retained normally. Numeric HTTP status, Result-Status and RPC errors observed in recognized vendor log formats are retained separately without copying surrounding messages, headers, signatures or tokens. This prevents verbose SDK diagnostics from displacing the final SDK return or observed error codes. Completeness applies to this declared capture policy, not every formatted vendor message. Drain/reset it after the SDK worker joins; it performs no file or console IO during calls. Raw prefixes require explicit private capture and retain the original observed length, digest, prefix length and truncation/drop counters. SDK logs are formatted vendor messages, not a supported HTTP plaintext export. Socket data is below vendor TLS and must not be labeled decoded RPC. No TLS verification or protocol is changed. Complete HTTP headers/bodies, TLS handshake results and signatures require a supported plaintext boundary in a future SDK delivery; they cannot be inferred from a socket trace or PCAP. Operation-Type is recorded only when that exact header is observed in an SDK log.

The target injects Memory, Time, Sync, Crypto, Net, Netif and Pref PALs and product identity callbacks. The ESP facade retains its names and defaults the MAC callback to `ESP_MAC_BT`. `sdk_test` uses original headers and controlled SDK entry stubs to test PAL error mapping, initialization caching, identity and callbacks. It does not qualify the vendor binary or service. Run `bazel test --config=macos_arm64 --repo_env=ALIPAY_SDK_PATH //projects/testing/integration/alipay/vendor_sdk:sdk_test`; real qualification builds and installs the original-SDK integration target.

## Binding completion and KV

The shared API now exposes optional `query_binding_result` and `binding_snapshot` operations. After this SDK instance generates and displays its binding code, `query_binding_result` invokes the original `alipay_query_binding_result`. The vendor owns queryBindInfo, ECDH processing, PSA writes and finishBind. The adapter checks both the actual SDK return and the output status; this delivery can return zero while its output still means pending or failed.

The default Pref-backed adapter commits the vendor's original records without changing their contents:

| SDK item | KV key | Meaning |
| --- | --- | --- |
| 1 | `p00000001` | 32-byte ECDH shared key |
| 2 | `p00000002` | Seed material |
| 6 | `p00000006` | TID |
| 7 | `p00000007` | UID |

Only after SDK completion, successful mutations and readback of all four records does the adapter commit and reread `binding_ready`. This versioned record fingerprints the four stored values and is invalidated before their mutation. It is a local consistency record, not a server credential. The public result and trace expose status and lengths only. SDK namespaces and certificate retention keep their existing behavior; the final entry still chooses the storage provider and namespace.

A marker commit failure can be retried locally in the same boot after the SDK has completed; queryBindInfo and finishBind are not repeated. A failed SDK material write is not promoted to success by a later read. Startup `binding_snapshot` makes no RPC and requires both the SDK's local bound state and matching persisted records. Missing, corrupt or legacy unverified records require explicit verification; the adapter does not reset or automatically rebind them.

These completion operations require default Pref storage (`secure == NULL`); unsupported storage propagates as an error. Existing explicit storage overrides retain the original bridge behavior. The [SDK-only integration entry](../README.md) displays the SDK's own code and polls that same session. Independent tokens and temporary keys are never mixed into this flow.
